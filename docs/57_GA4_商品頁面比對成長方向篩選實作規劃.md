# 57_GA4 商品頁面比對成長方向篩選實作規劃

## 背景

延續 [[55_GA4_到達頁與商品成長方向篩選實作規劃]]、[[56_GA4_商品頁面比對上一期比較功能實作規劃]]：到達頁跟商品分頁已經有「指標＋方向」篩選，商品頁面比對分頁（`ItemLandingCrossTab`）的比較功能是 docs/56 才做的，還沒有補這個篩選。

## 拍板決策

沿用 docs/55 原班決策，不重新討論：

1. 兩個下拉選單：指標 + 方向（全部/上升/持平/下降），只篩單一指標
2. 不同步到 AI 解讀（`buildPayload`/`contextLabel` 不受影響）
3. 不同步到分享連結網址與分享頁 UI

## 跟到達頁/商品的差異

商品頁面比對每列其實是「商品」+「配對到的到達頁」兩個實體疊在一起，三個比較欄位分屬不同實體：

| 指標 | 欄位 | 所屬實體 | 空值情況 |
|---|---|---|---|
| 商品購買率 | `purchase_to_view_rate_delta_pp` | 商品 | `item_is_new` 為真時是 `null` |
| 到達頁轉換率 | `page_session_key_event_rate_delta_pp` | 到達頁 | 配對頁面上一期無資料時是 `null`（不特別標記，見 docs/56） |
| 到達頁工作階段 | `page_sessions_growth_rate` | 到達頁 | 同上 |

篩選邏輯不用區分這個差異——沿用 docs/55 同一條規則「選了指標後，該欄位為 `null` 的列一律被方向篩選排除（選『全部』不受影響）」，三個指標都適用，不用另外判斷 `item_is_new` 或到達頁是否缺資料。

## 技術方向

- `ItemLandingCrossTab.jsx` 新增 `ITEM_LANDING_GROWTH_METRIC_OPTIONS`（上表三個指標）、`itemLandingGrowthMetric`/`itemLandingGrowthDirection` 本地 state
- 兩個下拉只在 `itemLandingCompareEnabled` 為真時顯示，位置放在期間選擇器那排（跟到達頁/商品一致，篩選列在同一區塊）
- `rows` 的 `useMemo` 加上方向篩選（疊加在現有的 `itemsViewed` 排序之前），依賴陣列加上這兩個 state 跟 `itemLandingCompareEnabled`
- 關閉「比較上一期」開關時，重置這兩個 state 回預設值（比照 docs/55 步驟 1 的寫法）
- 純前端二次篩選，不動後端、不多打 API
