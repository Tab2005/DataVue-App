# 43_GA4 渠道值自訂分組擴充構想

## 背景

在測試 [[42_GA4_到達頁渠道篩選實作規劃|到達頁渠道篩選]] 功能時發現：選「工作階段來源/媒介」維度時，同一個廣告平台的流量常常因為 UTM 標籤寫法不一致（例如同樣是 Facebook 廣告，`medium` 有時標 `cpc`、有時標 `post-ads`、有時標 `paid`），被拆成好幾筆不同的渠道值，篩選時要一個一個切換才能看完整的「這個平台的付費流量」。

改選「工作階段來源」維度雖然能把 `facebook / post-ads`、`facebook / cpc` 等合併成一筆 `facebook`，但這樣連 Facebook 的自然（非付費）流量也會被一起算進去，混淆了「這是不是花錢投放的流量」這件事——使用者明確表示需要保留付費/自然的區隔，不能用這種太粗的合併方式。

## 需求

讓使用者可以自訂規則，把多個原始渠道值（例如 `facebook / post-ads`、`facebook / cpc`、`facebook / paid-social`）歸到同一個自訂分組標籤（例如「Facebook 付費廣告」），篩選到達頁時能直接選這個分組，而不用切換好幾次原始值。

## 現況：已有類似前例可以參考

系統裡已經有兩套「自訂規則歸類」的功能，設計模式可以直接沿用：
- 到達頁分類規則 `GA4LandingPageRule`（`backend/database/models/ga4_insights.py`）：`category` + `match_type`（prefix/contains）+ `pattern` + `priority`，依優先序找第一個比對成功的規則
- 商品分類規則 `GA4ItemCategoryRule`：同樣的 `match_type`/`pattern`/`priority` 結構，只是 `category` 是自由文字

渠道值分組可以比照同一套結構：`GA4ChannelGroupRule`（暫名）——`channel_dimension`（比對哪個維度的值，如 `source_medium`）、`group_label`（自訂分組名稱，自由文字）、`match_type`（prefix/contains）、`pattern`、`priority`。

## 跟純分類規則不同、需要多想的地方

到達頁/商品分類規則只是「把查詢結果的每一列，事後貼一個分類標籤」，不影響 GA4 查詢本身。但渠道值分組不一樣：使用者選了「Facebook 付費廣告」這個分組後，**GA4 查詢本身要把符合規則的所有原始渠道值都篩進去**（等於一次篩選好幾個原始值的聯集），而不是像現在的 `dimension_filter` 只能篩一個精確值。

查過 `google.analytics.data_v1beta.types`，GA4 Data API 有兩種方式可以做「篩多個值的聯集」：
- `Filter.InListFilter`：精確值列表（例如直接給 `["facebook / post-ads", "facebook / cpc"]`）
- `FilterExpression.or_group`：把多個 `FilterExpression`（各自可以是 `Filter.StringFilter` 的 prefix/contains 比對）用 OR 組合起來

沿用既有規則系統的 prefix/contains 語意（不是精確值列表），應該用 `or_group` 把每一條符合的分組規則各自轉成一個 `Filter.StringFilter`（`BEGINS_WITH`/`CONTAINS` 對應 prefix/contains），再用 OR 組合成一個查詢送出去。這代表 [[42_GA4_到達頁渠道篩選實作規劃|42 號]] 已經做好的 `dimension_filter: Tuple[str, str]`（單一維度＋單一精確值）不夠用了，`GA4Service.get_analytics` 要再擴充成能接受「多個比對條件的 OR 組合」，不只是單一精確值。

## 使用情境需要決定的事

1. 「渠道值」下拉選單要怎麼呈現分組後的選項：是把「自訂分組」跟「原始值」混在同一個下拉裡（例如「Facebook 付費廣告（自訂分組）」排在原始值列表最前面），還是分開兩個下拉？
2. 一個原始渠道值如果同時符合多條分組規則，比照既有規則「依 priority 排序取第一個比對成功的」，還是允許重疊（一個原始值可以同時屬於多個分組）？
3. 分組規則要跟哪個維度綁定——使用者選「來源/媒介」維度時定義的分組規則，能不能也套用在「來源」或「媒介」維度上？（傾向不行，三個維度的值格式不同，規則直接綁定單一維度比較單純，不跨維度共用）
4. 是否需要規則管理 UI（新增/刪除/排序），比照到達頁/商品分類規則現有的「分類規則」收合面板

## 狀態

僅記錄構想，尚未排入實作規劃。比 [[42_GA4_到達頁渠道篩選實作規劃|42 號]] 複雜——42 號只需要「單一維度＋單一精確值」的篩選，這個構想需要「單一維度＋多個比對條件的 OR 組合」，屬於在 42 號基礎上的進一步擴充，建議 42 號先上線驗證過渠道篩選本身沒問題後，再評估是否要做這層分組。
