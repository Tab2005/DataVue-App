# 45_GA4 商品渠道篩選實作紀錄

## 背景

到達頁分頁已有「維度／渠道值／自訂分組」三層渠道篩選（見 [[42_GA4_到達頁渠道篩選實作規劃]]、[[44_GA4_渠道值自訂分組實作規劃]]，兩者皆已驗收完成）。使用者確認到達頁的渠道分組功能實測沒問題後，詢問商品分頁是否也能有相同功能，討論後直接動工，故本文件用「實作紀錄」而非事先的「實作規劃」格式——設計已在對話中確定，完工後補記錄。

## 關鍵設計決策

1. **規則共用，不重建**：`GA4ChannelGroupRule` 本來就是綁「維度」而非綁「到達頁」，商品分頁直接沿用到達頁已建立的分組規則（例如「Facebook 付費廣告」），選同一個維度就會看到，不用另外維護一份。
2. **篩選只套用在主表格，不套用在成長比較／分類拆解**：
   - 商品分析原本就有兩個獨立於「上方期間選擇」的查詢：`views_growth_rate`（固定近 7 天 vs 前 7 天）與 `itemName × itemCategory` 分類拆解。
   - 與使用者確認：這兩個維持全渠道口徑，不隨渠道篩選變動——理由是 (a) 成長比較本來就已經是「跟期間選擇無關」的獨立指標，使用者已經習慣它是另一套口徑；(b) 分類拆解只是「商品該分到哪一類」的靜態依據，不是渠道相關指標。
   - 表頭 ⓘ 提示文字同步更新為「固定用近 7 天 vs 前 7 天（全渠道，不受下方篩選影響）」，避免誤讀成「該渠道的成長」。

## 實作內容

### 後端

- `backend/modules/ga4/insights/items.py::get_items`
  - 新增 `channel_dimension`／`channel_value`／`channel_group` 三個參數，驗證邏輯完全比照到達頁（`channel_value`/`channel_group` 互斥、需搭配 `channel_dimension`、白名單檢查）
  - `channel_group` 時呼叫既有的 `get_channel_group_match_conditions`（`channel_groups.py`，到達頁與商品共用同一支）組出 OR 篩選；`channel_value` 時組單一精確值篩選
  - **`dimension_filter` 只傳給主查詢**（`ITEM_METRICS_WITH_OFFICIAL_RATES`/`ITEM_METRICS_FALLBACK`），近 7 天/前 7 天瀏覽成長比較的兩支查詢與 `itemName × itemCategory` 分類拆解查詢維持不帶篩選
  - payload 新增 `channel_dimension`/`channel_value`/`channel_group` 欄位
  - snapshot `kind` 比照到達頁：`item`、`item:ch_{hash}`（精確值）、`item:chg_{hash}`（自訂分組），篩選前後的快照互不覆寫
- `backend/modules/ga4/insights_router.py::GET /items`
  - 新增 `channel_dimension`/`channel_value`/`channel_group` query 參數，補上 `ValueError` → 400 的例外處理（原本只接 `RuntimeError`）
  - `/channel-group-rules`、`/channel-groups` 等既有端點不用改，本來就是通用（不綁分頁）
- 測試：`backend/tests/test_ga4_item_analysis.py` 新增 10 個測試
  - 精確值篩選只作用在主查詢、成長比較/分類拆解查詢不帶篩選
  - `channel_value`/`channel_group` 互斥、缺維度、白名單外維度、找不到分組等驗證
  - 自訂分組 OR 篩選正確組成
  - 精確值篩選與分組篩選各自獨立存快照
  - 端點層：接受 `channel_value`/`channel_group`、兩者併給回 400、白名單外維度回 422

### 前端

- `frontend/src/services/ga4InsightsService.js::getItems` 新增 `channelDimension`/`channelValue`/`channelGroup` 參數（沿用既有的 `listChannelGroupRules`/`upsertChannelGroupRule`/`deleteChannelGroupRule`/`listChannelGroups`，不用新增 API 方法）
- `frontend/src/pages/GA4Insights.jsx`
  - 新增商品分頁專屬的渠道篩選 state（`itemsChannelDimension`/`itemsChannelValue`/`itemsChannelGroup` 等，跟到達頁那組互相獨立，各自記自己選的維度/值/分組）
  - 新增 `loadItemsChannelValues`/`loadItemsChannelGroups`/`loadItemsChannelGroupRules`/`handleCreateItemsChannelGroupRule`/`handleDeleteItemsChannelGroupRule`
  - `loadItems` 簽章擴充為接受 `channelDimension`/`channelValue`/`channelGroup`
- `frontend/src/components/GA4Insights/ItemsTab.jsx`
  - 篩選列新增「維度／渠道值／自訂分組」三個下拉，跟到達頁同一套互斥邏輯（選渠道值清空自訂分組，反之亦然；切換維度兩者都清空）
  - 新增「渠道分組規則」收合面板，跟到達頁外觀一致，並註明「規則跟到達頁分頁共用」避免使用者誤以為要重建
  - 「瀏覽成長」表頭 ⓘ 提示文字更新，明確標註不受渠道篩選影響

- 前端：`vite build` 編譯成功
