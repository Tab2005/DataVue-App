# 58_成效分析頁 AI 廣告分析改版實作規劃

## 背景

「深度成效分析」頁（`Analytics.jsx`，Facebook Ads 專用）目前有一個「🤖 AI 廣告分析」按鈕，放在頂部篩選列（`AnalyticsFiltersPanel.jsx`），點下去會從右側滑出一個面板（`AnalyticsAiPanel.jsx`），面板裡還要再按一次「開始分析」才真的呼叫 AI。使用者想比照 GA4 轉換洞察頁面下方「AI 白話解讀」的模式（`GA4InsightsShared.jsx::AIInsightNote`）：改成表格下方一張固定卡片、按鈕直接觸發生成，解讀內容要跟著「目前選擇的指標」與「目前表格實際顯示的資料」走，**並且加上持久化儲存與分享連結**（確認後追加的範圍，比照 GA4 docs/39 的做法）。

## 現況問題

1. **UI 是滑出面板**，不是像 GA4 那樣內嵌在表格下方的卡片，操作路徑也多一層（開面板 → 按開始分析，共兩次點擊）。
2. **Payload 內容寫死**：`handleStartAnalysis`（`Analytics.jsx:346`）送給 AI 的摘要固定是 `total_spend`/`total_roas`/`total_purchases` 三個指標，不管使用者實際在「自訂表格指標欄位」勾了哪些（`selectedMetrics`/`activeCols`）。
3. **rows 跟畫面對不上**：直接送 `filteredData.slice(0, 20)`——是篩選後但**未依目前欄位排序**的前 20 筆，且是完整 row 物件（帶所有原始欄位，不只使用者勾選要看的）。畫面上實際排序顯示的是 `sortedData`，兩者可能不同。
4. **沒有帶 `report_type`**：後端 `AIService.analyze_data()` 預設走 `ad_analysis` 分支，是最陽春的英文 prompt，沒有套用其他 report_type 共用的 `markdown_format_spec`。
5. **完全沒有持久化**：解讀內容只存在元件記憶體，關閉面板/切換篩選/重新整理就消失，也無法分享給團隊其他人看。

## 跟 GA4 AIInsightNote 的差異（設計取捨）

GA4 轉換洞察頁的「AI 白話解讀」背後是 `GA4InsightsSnapshot` 這張表，運作方式是：**每次 GET 報表資料時後端就自動 upsert 一筆快照**（key 是 `property_id + kind + date`），AI 解讀跟分享連結都掛在這筆已存在的快照上。

成效分析頁的表格沒有這種「固定 key 的每日快照」概念——資料是即時運算，會隨篩選/排序/日期/勾選指標隨時變動，沒有天然的 upsert key。因此這次改用**「按按鈕的當下才建立快照」**的模式：

- 使用者點「開始 AI 解讀」時，前端先把當下的 `buildPayload()` 結果（已勾選指標＋依畫面排序的前 20 筆資料＋日期範圍/層級）送到後端，**建立一筆新快照**，拿到 `snapshot_id`
- 同一份 payload 同時送去給 AI 串流分析，完成後把結果存回這筆快照的 `ai_summary`
- 「產生分享連結」比照 GA4，掛在這筆快照上
- **每次點「開始 AI 解讀／重新解讀」都會建立一筆全新的快照**（不像 GA4 同一個 kind+date 會重複覆蓋同一筆）——好處是分享連結一旦產生，內容永久凍結在分享當下的樣子，之後使用者再重新解讀、改篩選都不會影響已經分享出去的連結內容，語意更單純

## 拍板決策

1. **完全移除舊的滑出面板**：拿掉 `AnalyticsFiltersPanel.jsx` 頂部的「AI 廣告分析」按鈕、刪除 `AnalyticsAiPanel.jsx`（已確認全專案只有 `Analytics.jsx` 引用）
2. **Payload 跟著「使用者選擇的指標」走**：`selected_metrics` 取自 `activeCols`（含 `key`/`label`/`format`）；`summary` 從既有的 `currentSummaryData`（口徑正確的加總/加權平均）只挑 `selected_metrics` 涵蓋的 key；`rows` 改用 `sortedData`（跟畫面排序一致）取前 20 筆，每筆只留 `{ name, ...selected_metrics 的值 }`
3. **後端新增 `analytics_table` report_type**：prompt 明確規則「只根據 payload 的 `selected_metrics` 分析，使用者沒勾選的指標不要提及」，不沿用 `weekly_summary` 那組寫死「花費/ROAS/成交數」範例的 Facebook prompt
4. **新增獨立資料表 `fb_ads_analytics_ai_snapshots`**（不是重用 `WeeklyReport`）：`WeeklyReport` 背後是完整的週報專案機制（草稿/產生/排程、有自己的列表頁與 `/generate` 重新查詢 FB API 的邏輯），語意跟用途都跟這裡要的「輕量快照＋AI 解讀＋分享」不同，混用會讓這張快照意外出現在使用者的「週報」列表裡，造成困惑
5. **不做「儲存為草稿」等中間狀態**：一點「開始 AI 解讀」就是完整流程（建快照 → 呼叫 AI → 存回 ai_summary），沒有像週報那樣的 draft 狀態
6. **rows 筆數維持 20**

## 技術方向

### 後端

- **新資料表**：`backend/database/models/fb_ads.py`（新檔案）新增 `FbAdsAnalyticsAiSnapshot`：
  - `id`（`fas_{uuid}`）、`account_id`（String，index）、`team_id`（String，FK `teams.id`，nullable）
  - `level`（campaign/adset/ad/account）、`date_since`、`date_until`
  - `payload`（JSON，即 `selected_metrics`/`summary`/`rows`）
  - `ai_summary`（Text，nullable）、`ai_summary_generated_at`（DateTime，nullable）
  - `share_token`（String(64)，unique，nullable，index）
  - `created_by`（FK `users.id`）、`created_at`
  - 在 `backend/database/__init__.py` 匯出，比照 `GA4InsightsSnapshot` 的匯出方式
- **Migration**：新增 `create_table`（比照 `20260710_ga4_insights_tables.py` 的 `_table_exists` 冪等寫法）
- **Repository**：`backend/modules/fb_ads/analytics_ai_repository.py`（或直接寫在新 service 裡，視程式碼量決定）：`create_snapshot` / `get_snapshot_by_id` / `update_ai_summary` / `get_or_create_share_token` / `get_snapshot_by_share_token`
- **`backend/ai_service.py::analyze_data()`** 新增 `report_type == "analytics_table"` 分支（沿用 `markdown_format_spec`；報告結構：`## 一句話總結` → `## 指標表現解讀` → `## 可以做的一件事`）
- **新 router**：`backend/routers/analytics_ai.py`（prefix `/api/analytics-ai`，比照 GA4 `insights_router.py` 的獨立檔案模式，掛進 `main.py`）：
  - `POST /snapshots`：`{account_id, team_id, level, date_since, date_until, payload}` → 建立快照，回傳 `{snapshot_id, payload, ai_summary: null, ...}`（需登入 + `fb_ads_check`，比照 `/api/analytics-data`）
  - `PUT /snapshots/{snapshot_id}/ai-summary`：`{ai_summary}` → 存回，回傳序列化後的快照
  - `POST /snapshots/{snapshot_id}/share`：取得或建立 `share_token`
  - `GET /share/{token}`：**公開端點，不需登入**，回傳 `{account_id, level, date_since, date_until, payload, ai_summary, ai_summary_generated_at}`

### 前端

- 新增 `frontend/src/services/analyticsAiService.js`：`createSnapshot(payload)` / `saveAiSummary(snapshotId, aiSummary)` / `createShareLink(snapshotId)` / `getSharedSnapshot(token)`（比照 `ga4InsightsService.js`，公開端點用 `skipAuth: true`）
- 新增 `frontend/src/components/Analytics/AnalyticsAiInsightCard.jsx`：
  - 樣式比照 `AIInsightNote`（卡片、標題+說明、右上角按鈕、白話解讀顯示區、免責聲明、分享連結區塊）
  - `handleGenerate`：呼叫 `analyticsAiService.createSnapshot(buildPayload())` 拿 `snapshot_id` → 用 `aiService.analyzeDataStream()` 送同一份 payload 串流生成 → 完成後 `analyticsAiService.saveAiSummary(snapshot_id, 內容)`
  - `handleShare`/`handleCopyLink`：比照 `AIInsightNote`，連結格式 `/analytics/share/{token}`
  - Props：`buildPayload`（由 `Analytics.jsx` 組出）、`contextLabel`、`language`、`disabled`（無資料時禁用）
- `Analytics.jsx`：
  - 刪除 `showAiPanel`/`isAnalyzing`/`analysisResult`/`aiError` state 與 `handleStartAnalysis`
  - `<AnalyticsAiPanel>` 換成 `<AnalyticsAiInsightCard>`，位置在 `<AnalyticsDataTable>` 之後
  - 新增 `buildAnalyticsAiPayload()`：組出 `selected_metrics`（`activeCols` 的 `key`/`label`/`format`）、`summary`（`currentSummaryData` 篩出 selected keys）、`rows`（`sortedData.slice(0, 20)` 只留 name + selected metrics）、`level`/`date_since`/`date_until`/`account_id`
- `AnalyticsFiltersPanel.jsx`：移除「🤖 AI 廣告分析」按鈕與 `setShowAiPanel` prop
- 刪除 `frontend/src/components/Analytics/AnalyticsAiPanel.jsx`
- 新增 `frontend/src/pages/SharedAnalyticsInsight.jsx`（公開唯讀頁）：顯示層級/日期範圍、一個簡單表格（name + 選中的指標欄位，依 `format` 做基本格式化）、AI 解讀（ReactMarkdown）
- `App.jsx`：新增 `<Route path="/analytics/share/:token" element={<SharedAnalyticsInsight />} />`（lazy import，比照 `/ga4-insights/share/:token`）
