# 39_GA4 轉換洞察快照分享連結實作計劃

## 背景與需求

`/ga4-insights` 頁面（GA4 轉換洞察）的「渠道對照」「到達頁」「商品」三個分頁，各自可對當前快照按「開始 AI 解讀」產生一段 AI 白話分析文字（`AIInsightNote`，存於 `ga4_insights_snapshots.ai_summary`）。

使用者需求：AI 解讀完成的當下，就能在原地產生一個「分享連結」，不需登入即可打開，把當次的數據＋AI 解讀文字原樣呈現給其他人看（例如同事、主管）。

已討論並排除的方案：接入既有的週報系統（`WeeklyReport` / `share_token` / `/reports/share/:token`）。原因：週報系統目前 GA4 只抓 summary + trend + 籠統的 `sessionSourceMedium` 表格，並未涵蓋渠道對照/到達頁/商品這三塊的專屬邏輯與 AI 文字，要接進去改動範圍較大且脫離「當下頁面即時分享」的使用情境。

最終方向：直接在 `GA4InsightsSnapshot`（`ga4_insights_snapshots` 表）這個既有模型上加一個 `share_token` 欄位。這張表本身已經是「一次快照 = 一份數據(payload) + 一份 AI 解讀(ai_summary)」的完整記錄，天生適合拿來做分享，不需要另外設計資料結構。

範圍確認：分享連結為**單一分頁**（渠道對照 / 到達頁 / 商品各自獨立），不做多分頁打包成一份的功能。

## 現況（相關程式碼位置）

- 模型：`backend/database/models/ga4_insights.py:11` `GA4InsightsSnapshot`（`property_id` + `kind` + `date` 唯一鍵，`payload` JSON，`ai_summary` Text）
- Repository：`backend/modules/ga4/repository.py`（`GA4InsightsRepository`，`repository` 單例）
- Service 邏輯：`backend/modules/ga4/insights/`（`channels.py` / `landing_pages.py` / `items.py` / `kpi.py` 等），統一透過 `backend/modules/ga4/insights/__init__.py` 的 `GA4InsightsService` 對外
- 路由：`backend/modules/ga4/insights_router.py`，掛載於 `backend/main.py:229` prefix `/api/ga4/insights`
- 前端頁面：`frontend/src/pages/GA4Insights.jsx`（路由 `/ga4-insights`）
- 前端分頁元件：`frontend/src/components/GA4Insights/{ChannelsTab,LandingPagesTab,ItemsTab}.jsx`
- AI 解讀共用元件：`frontend/src/components/GA4Insights/GA4InsightsShared.jsx:357` `AIInsightNote`
- 前端 API client：`frontend/src/services/ga4InsightsService.js`
- 既有公開分享參考模式：`backend/routers/reports.py:331`（`GET /share/{token}`，無需登入）、`frontend/src/pages/SharedReport.jsx`、`frontend/src/services/reportService.js`（`skipAuth: true`）

## 實作內容

### 1. 資料庫

- `GA4InsightsSnapshot` 新增欄位 `share_token`（`String`，nullable，唯一索引）
- Alembic migration：新檔案，`down_revision` 接目前 head `20260714_ma_label_policy_cpm`，比照 `20260710_ga4_kpi_targets.py` 的 `_table_exists` / inspector 寫法風格，做成可重複執行的 idempotent migration（用 `add_column` + 建唯一索引，執行前檢查欄位/索引是否已存在）

### 2. 後端

- `repository.py` 新增：
  - `get_or_create_share_token(db, snapshot_id)`：已存在 token 就回傳原本的（避免每次點擊都換連結），沒有則產生 `uuid.uuid4().hex` 並存回去
  - `get_snapshot_by_share_token(db, token)`
- `insights/__init__.py`（`GA4InsightsService`）加對應包裝方法
- `insights_router.py` 新增兩個端點：
  - `POST /snapshots/{snapshot_id}/share`（需登入 + `require_ga4_insights_view`，比照 `save_ai_summary` 的權限層級）→ 回傳 `{snapshot_id, share_token}`
  - `GET /share/{token}`（**無任何 auth 依賴**，比照 `reports.py:331` 的公開端點寫法）→ 回傳 `kind`、`date`、`property_id`、`payload`、`ai_summary`、`ai_summary_generated_at`（不回傳 `fetched_by` 等內部使用者資訊）

### 3. 前端

- `ga4InsightsService.js` 新增：
  - `createShareLink(snapshotId)` → `POST /snapshots/{id}/share`
  - `getSharedSnapshot(token)` → `GET /share/{token}`，帶 `{ skipAuth: true }`（比照 `reportService.getSharedReport`）
- `AIInsightNote`（`GA4InsightsShared.jsx`）：AI 解讀有內容後，多一顆「產生分享連結」按鈕；點擊後呼叫 `createShareLink`，顯示連結（`/ga4-insights/share/{token}`）並提供一鍵複製
- 新增公開頁面 `frontend/src/pages/SharedGA4Insight.jsx`（比照 `SharedReport.jsx` 的版面：品牌 header + footer），依 `kind` 前綴（`daily_channel` / `landing_page` / `item`）渲染對應的唯讀數據表格（沿用 `GA4InsightsShared.jsx` 匯出的 `fmtNumber` / `fmtPct` / `tr` 等 helper），並在上方用 `ReactMarkdown` 呈現 `ai_summary`
- `App.jsx` 新增公開路由 `/ga4-insights/share/:token`，放在 `ProtectedRoute` 包住的 `Layout` 之外（比照 `/reports/share/:token` 的位置，第 64 行附近）

## 不在本次範圍內

- 不動既有週報（`WeeklyReport`）系統
- 不做多分頁打包成單一連結
- 不做連結到期時間 / 密碼保護（如未來需要可再加欄位）
