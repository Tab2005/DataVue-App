# 56_GA4 商品頁面比對上一期比較功能實作規劃

## 背景

延續 [[54_GA4_到達頁與商品上一期比較功能實作規劃]]：使用者測試後想知道「商品頁面比對」（`item_landing_cross.py`）能不能加上同一套「比較上一期」功能。

## 跟到達頁/商品不同的關鍵問題：主要到達頁的配對會隨期間變動

到達頁/商品的比較都是「同一個 key（頁面路徑/商品名稱）在兩期各查一次」，key 本身穩定。但商品頁面比對的核心是「商品 × 它的主要到達頁」這組配對，而**「主要到達頁」是依當期瀏覽量最高者決定的**（`item_landing_cross.py` 查詢 2）。如果直接對上一期也重新判定一次「哪個頁面瀏覽量最高」，配對出來的頁面可能跟本期不是同一個（例如活動期間導流的頁面換了），比較出來的「到達頁轉換率」就會變成拿兩個不同頁面比，語意不清楚。

## 拍板決策

1. **固定用本期算出來的配對**：上一期比較一律沿用本期查詢 2 決定的 `primary_landing_page_by_item`，不對上一期重新判定「哪個頁面才是主要頁面」——確保比較的是「同一組商品-頁面關係，前後表現有沒有變化」
2. 比較欄位：商品瀏覽後購買率（`purchase_to_view_rate`，比率→百分點差異）、到達頁轉換率（`page_session_key_event_rate`，比率→百分點差異）、到達頁工作階段（`page_sessions`，次數→相對成長率）——對應表格目前實際顯示的三欄
3. 新舊判定拆成兩個獨立情況（跟到達頁/商品單一 `is_new` 不同，因為這裡牽涉兩個實體）：
   - `item_is_new`：這個商品在上一期完全沒有資料 → 商品購買率不顯示成長標示，顯示 🆕
   - 到達頁那三欄（頁面工作階段/轉換率）：只要「本期配對到的那個頁面」在上一期沒有資料，該列的頁面比較欄位就顯示為「無資料」（不特別加 🆕 標記，因為配對頁面沒資料可能只是這個頁面剛好在查詢期間流量掛零，不一定是「新頁面」，跟到達頁/商品分頁「這一整列都是新的」語意不同）
4. 這次**只做**「開關 + 比較數字顯示」，比照 docs/54；**不**加 docs/55 那種「指標＋方向篩選」，之後有需要再另外評估
5. 開關預設關閉，跟既有三支查詢一樣，比較查詢個別失敗只記警告、不擋主表格

## 技術方向

### 後端

- `get_item_landing_cross()` 新增 `compare: bool = False` 參數
- `compare=True` 時多兩支查詢（沿用主查詢的日期偏移邏輯，跟 docs/54 一致）：
  - 商品指標（跟查詢 1 同一組指標集，依 `used_fallback_conversion_metrics` 決定官方或 fallback）→ 算出每個商品上一期的 `purchase_to_view_rate`
  - 到達頁指標（跟查詢 3 同形狀，`dimensions=["landingPage"]`）→ 查出上一期「所有」到達頁的數據，但**只用來查本期配對頁面的上一期表現**，不重新跑一次商品×到達頁的配對查詢
- 兩支比較查詢各自獨立容錯（`item_compare_query_error`/`landing_compare_query_error`），失敗時對應的比較欄位留 `None`，不影響主表格
- payload 每列新增：`item_is_new`、`purchase_to_view_rate_prior`/`_delta_pp`、`page_sessions_prior`/`_growth_rate`、`page_session_key_event_rate_prior`/`_delta_pp`
- payload 頂層新增：`compare_enabled`、`compare_start_date`、`compare_end_date`、`item_compare_query_error`、`landing_compare_query_error`
- `kind` 加 `:cmp` 後綴（跟到達頁/商品一致）

### 前端

- `insights_router.py` 的 `/item-landing-cross` 端點、`ga4InsightsService.js` 的 `getItemLandingCross` 都加 `compare` 參數（比照到達頁/商品的路由 + service layer 串接）
- `GA4Insights.jsx`：新增 `itemLandingCompareEnabled` state，開關切換時重新請求資料
- `ItemLandingCrossTab.jsx`：期間選擇器旁加「比較上一期」開關；三個比較欄位加成長標示（`GrowthBadge`，複製自到達頁/商品分頁同一套邏輯：次數用相對成長率、比率用百分點差異+pp提示）；商品購買率是 `item_is_new` 時顯示 🆕，頁面兩欄若對應頁面上一期無資料則顯示現況數字、不加成長標示（不特別標記）
- `contextLabel`/`buildPayload` 補上比較狀態說明（比照到達頁/商品）
- `SharedGA4Insight.jsx` 的 `ItemLandingCrossTable`：一併補上同一套成長標示顯示（吸取 docs/54 那次「分享頁忘了同步」的教訓，這次直接在同一輪做完，不用之後再補）

## 附加小需求：表格分頁補「共 N 筆」

使用者反映目前表格分頁只顯示「第 X / Y 頁」，沒有顯示總筆數。這是共用元件 `GA4InsightsShared.jsx::TablePager` 本身沒有這個資訊，目前到達頁、商品、商品頁面比對、告警歷史這 4 個分頁都用同一個 `TablePager`，補上去這 4 個地方會一起受惠。

- `TablePager` 新增可選 prop `totalItems`；有傳的話文字改成「共 {totalItems} 筆・第 X / Y 頁」，沒傳（維持向下相容）就跟現況一樣只顯示「第 X / Y 頁」
- 4 個呼叫端（`LandingPagesTab.jsx`／`ItemsTab.jsx`／`ItemLandingCrossTab.jsx`／`AlertsTab.jsx`）都補上 `totalItems={filteredSortedXxx.length}`（篩選後的筆數，不是全部原始筆數，這樣「共 N 筆」才會跟畫面上實際看到的列數一致，篩選條件變動時數字也會跟著變）
