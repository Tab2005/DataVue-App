# 61_GA4 分享連結凍結副本實作規劃

實作日期：2026-07-31
對應項目：docs/59「建議處理順序」第 2 項 —— **P0-1 重新載入分頁會清空已分享出去的 AI 解讀，且分享內容會靜默變動**
狀態：**已完成**（後端 209 個 GA4 測試全數通過，含本次新增的 9 個測試；migration 已對 SQLite 實跑驗證 upgrade/重跑/downgrade）

---

## 1. 問題重述

`share_token` 掛在 `ga4_insights_snapshots` 這張**工作快照**表上，而工作快照的 key 是 `(property_id, kind, date)`，每次 GET 報表都會 upsert 覆寫 `payload`、並把 `ai_summary` 重設為 `None`——但**不會動 `share_token`**。

```
使用者開啟到達頁分頁          → 建立快照
產生 AI 解讀                  → ai_summary 寫入
產生分享連結、寄給客戶        → share_token 建立
使用者當天再次開啟同一個分頁  → upsert 覆寫 payload、ai_summary 被清成 None
客戶此時打開連結              → 連結有效，但解讀是空的，數字也跟寄出時不同
```

也就是說：**分享出去的「快照」其實不是快照，是一個會跟著動的即時視圖。**

---

## 2. 方案選擇

docs/59 提了兩個方向，本次採用**推薦解**：分享的當下複製一份不可變副本。

| 方案 | 取捨 |
|---|---|
| **（採用）分享時複製不可變副本** | 語意最乾淨，與 docs/58 成效分析頁「分享即凍結」一致，兩個模組不再各說各話 |
| 次佳：`upsert_snapshot` 偵測到 `share_token` 非空就另開新列 | 改動更小，但工作快照表會混進「已分享」與「工作中」兩種語意的列，且 `(property_id, kind, date)` 唯一鍵會擋住第二列 |

### 為什麼是獨立資料表，而不是同表加後綴

工作快照表有 `UniqueConstraint(property_id, kind, date)`。若把副本塞回同一張表，就得在 `kind` 後面接分享序號或 token 來避開唯一鍵——而 `kind` 是 `String(80)`，docs/22 當初就已經為了長度問題把渠道篩選改成短雜湊（見 `landing_pages.py` 的 `kind` 註解）。再往上疊只會重演同一個坑。

改用獨立表 `ga4_shared_snapshots` 後：沒有唯一鍵衝突、沒有長度上限問題、migration 是純新增（`CREATE TABLE` + 資料搬移），完全不動既有的約束。這也正是 docs/58 為成效分析頁選擇獨立表的同一個理由。

---

## 3. 重複點擊「產生分享連結」的語意

這是本次唯一需要新定案的行為。原本是「永遠回傳同一個 token」（`get_or_create_share_token`）。改成凍結副本後，若仍死守這個規則會有新問題：

> 早上分享（凍結 v1）→ 下午重新載入拿到新數據 → 再按分享 → 拿回 v1 的連結

使用者以為分享的是眼前這份，實際寄出的是早上那份。這只是把「內容會變」換成「分享到舊資料」，一樣誤導。

**定案：比對來源快照的 `payload` 與 `ai_summary`，沒變就沿用同一個 token，變了就凍結一份新的。**

- 連點兩下、同一份畫面重新開分享 → 同一個 token（不會產生一堆重複連結，既有的 idempotent 測試也繼續成立）
- 重新載入拿到新數據後再分享 → 新 token，且**舊連結仍指向舊內容**（舊的凍結副本不動）

## 4. 實作內容

### 4.1 新資料表 `ga4_shared_snapshots`（`database/models/ga4_insights.py`）

| 欄位 | 說明 |
|---|---|
| `id` | `gss_` 前綴 |
| `source_snapshot_id` | 只用來判斷「來源自上次分享後有沒有變」；刻意不設級聯刪除——副本的意義就是不受來源後續變動影響 |
| `property_id` / `kind` / `date` | 複製自來源，供分享頁顯示與授權判斷 |
| `payload` / `ai_summary` / `ai_summary_generated_at` | 凍結的內容本體 |
| `share_token` | `nullable=False`, unique, index（副本必然帶 token，不像舊表是可為 null 的附加欄位） |
| `created_by` / `created_at` | 稽核用 |

寫入後**永不更新**。

`GA4InsightsSnapshot.share_token` 標記為已停用並加註警語，但**不刪除**：保留可回滾餘地、不破壞既有資料。

### 4.2 Repository

移除 `get_or_create_share_token` / `get_snapshot_by_share_token`（舊表版本），新增：

- `create_shared_snapshot(db, *, source)`
- `get_latest_shared_snapshot_for_source(db, *, source_snapshot_id)`
- `get_shared_snapshot_by_token(db, token)`

### 4.3 Service（`insights/sharing.py`）

`create_share_link` 改為：查來源 → 比對最近一份副本 → 沿用或凍結新的。`get_snapshot_by_share_token` 改讀新表。函式名稱與 router 介面不變。

### 4.4 Router

`POST /snapshots/{id}/share` 的回應：`snapshot_id` 仍是**被分享的那筆工作快照**（欄位語意不變，前端沿用），副本自己的 id 另立 `shared_snapshot_id`。`GET /share/{token}` 與 `serialize_shared_snapshot` 完全不用改——新模型的欄位名與舊的一致。

docs/60 加的授權檢查也不受影響：它擋的是來源 `snapshot_id`，仍走 `repository.get_snapshot_by_id`。

### 4.5 Migration `20260731_ga4_shared_snapshots`

- `CREATE TABLE` + 3 個索引（share_token unique、property_id、source_snapshot_id），全部 check-before-create
- **資料搬移**：把既有 `share_token IS NOT NULL` 的工作快照複製進新表，**已經發出去的連結繼續可用**。以 `share_token` 判重，重跑不會重複插入
- 讀寫都走 SQLAlchemy Core 的 typed selectable：`payload` 是 JSON 欄位，Postgres 回傳已解析的 dict、SQLite 回傳字串，用 raw SQL 直接搬會在其中一邊壞掉

> 搬移只能凍結「migration 執行當下」的內容——在此之前這些 payload 本來就隨 upsert 變動過，無法回溯還原。

## 5. 測試

新增 `backend/tests/test_ga4_share_link_freeze.py`（9 個）：

1. **docs/59 P0-1 的原始重現情境**：分享 → 用真正的 `upsert_snapshot` 模擬重新載入分頁（斷言確實是同一列被覆寫、`ai_summary` 真的被清成 `None`、payload 真的變 137）→ 公開端點仍回傳 100 與原本的解讀
2. 分享後改寫來源的 AI 解讀 → 連結不受影響
3. 內容沒變重複分享 → 同一 token、只有一份副本
4. 內容變了再分享 → 新 token，且新舊連結各自指向各自的內容
5. 公開端點不洩漏 `fetched_by` / `created_by` / `source_snapshot_id` / `id`
6. 回應的 `snapshot_id` / `shared_snapshot_id` 語意
7. 未知 token → 404
8. **migration 資料搬移**：舊 token 搬移後仍能透過公開端點打開
9. **migration 重跑 idempotent**

另外對 migration 本身做了一次 SQLite 實跑煙霧測試（未納入 repo）：走到 `create_table` 分支、建出 3 個索引、搬移 1 筆舊連結、重跑不重複、`downgrade()` 乾淨移除。

## 6. 前端

**不需要改動。** 前端只用回應裡的 `share_token`，且 `AIInsightNote` 在 `snapshot_id` 或 `ai_summary` 變動時就會把 `shareToken` 重設為 null、要求使用者重新按分享——正好對應「內容變了就凍結新副本」的後端語意。
