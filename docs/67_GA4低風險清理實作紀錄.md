## P2-4：移除測試用的反射 hack

`_shared.py` 有三個在執行期反查 facade 的 helper：

```python
def _service_attr(name, fallback):          # 反查 GA4InsightsService.<name>
def _facade_attr(name, fallback):           # 反查 insights_service.<name>
def _get_channel_min_sample():              # 反查 insights_service.CHANNEL_MIN_SAMPLE
```

存在的唯一理由是讓測試能 monkey-patch facade 上的同名屬性。代價是正式路徑上每次
呼叫都多一次 `sys.modules` 查表 ＋ 兩次 `getattr`，而且「這裡到底會執行哪個函式」
無法從程式碼靜態判讀。

**做法**：28 個呼叫點全部改成直接引用（`_service_attr("_trailing_period",
_trailing_period)(days)` → `_trailing_period(days)`），三個 helper 與跟著沒用的
`import sys` 一併移除。

**測試連動**：實際盤點下來只有 11 個 patch 目標靠這層間接，改指到定義處即可：

| 原本 | 改成 |
|---|---|
| `insights_service.GA4InsightsService._trailing_period` | `insights.items._trailing_period` |
| `insights_service.GA4InsightsService._fetch_intraday_dashboard_payload` | `insights.dashboard._fetch_intraday_dashboard_payload` |
| `insights_service.GA4InsightsService._fetch_metric_total` | `insights.dashboard._fetch_metric_total` |
| `insights_service.GA4InsightsService._historical_dates` | `insights.dashboard._historical_dates` |
| `insights_service.GA4InsightsService._get_attribution_model` | `insights.channels._get_attribution_model` |
| `insights_service_module.CHANNEL_MIN_SAMPLE`（`patch.object`） | `insights.channels.CHANNEL_MIN_SAMPLE` |

要 patch 使用處而不是定義處：子模組都是 `from ._shared import *`，`_trailing_period`
在 `items` 的命名空間是一份獨立的繫結，patch `_shared._trailing_period` 不會生效。

`_facade_attr` 的三個目標（`classify_landing_page` / `classify_item_category` 等）
**沒有任何測試在 patch**——那層間接純粹是白付的成本。

## P2-5：`__all__` 通配匯出

兩處都是：

```python
__all__ = [name for name in globals() if not name.startswith("__")]
```

`_shared.py` 這樣寫會把 `asyncio`、`logging`、`os`、`re`、`smtplib`、`sys`、
`datetime`、`median`、`User`、`GA4Service` 全部匯出；各子模組再 `from ._shared
import *`，等於每個檔案的命名空間都被塞滿無關符號。`insights/__init__.py` 再往上
放大一層，`insights_service.py` 又 `from .insights import *`。

**做法分兩層**：

1. **`_shared.__all__` 改成明確清單**——用 AST 算出「子模組真的有引用」的名字
   （46 個），砍掉 `logging` / `re` / `annotations` 等純噪音，以及三個沒有任何人用
   的常數（`KPI_PERIOD_TYPES`、`LANDING_PAGE_CATEGORIES`、`LANDING_PAGE_DEFAULT_KEYWORDS`，
   保留定義但不匯出）。
2. **stdlib 不再靠星號傳遞**——`os` / `smtplib` / `asyncio` / `datetime` / `median` /
   `EmailMessage` 從 `__all__` 拿掉，改由需要的子模組各自 `import`。這一步才是真的
   解掉問題：光是明列名單，看到 `median(...)` 還是不知道它從哪來。

`insights/__init__.__all__` 同樣改成明確清單：自己的公開 API ＋ 外部
（`insights_router` / scheduler / 測試 / conftest）確實會用到的那幾個 `_shared` 名字。

> 這裡踩了一次坑：第一版漏掉 `LANDING_PAGE_KEY_EVENT_PATTERN`（`insights_router.py`
> 有 `from .insights_service import` 它），整包測試在 collect 階段就 ImportError。
> 原因是掃描腳本把 `modules/ga4/insights_router.py` 也當成套件內部檔案排除掉了。
> 漏匯出的代價是 import 時直接爆，不是安靜的行為差異——這點反而讓它容易發現。

## P2-6：前端分頁 code splitting

`GA4Insights.jsx` 一次 import 全部 7 個分頁。把體積最大、且不是每個使用者都會開的
三個（到達頁、商品、商品頁面比對）改成 `lazy()`，沿用 `App.jsx` 既有慣例，
`Suspense` fallback 三個分頁共用一個。

| chunk | 之前 | 之後 |
|---|---|---|
| `GA4Insights` | 69.13 kB（gzip 16.43） | **37.02 kB（gzip 10.93）** |
| `LandingPagesTab`（新） | — | 14.24 kB（gzip 4.24） |
| `ItemsTab`（新） | — | 15.31 kB（gzip 4.78） |
| `ItemLandingCrossTab`（新） | — | 4.48 kB（gzip 2.03） |

只看當日總覽或告警的使用者，初始載入少了約 32 kB（gzip 5.5 kB）。

## 測試

新增 `backend/tests/test_ga4_namespace_hygiene.py`：釘住 P2-4 與 P2-5 的結果，避免
之後有人「順手」把反射層或通配匯出加回來。

- 反射 helper 不存在
- `_shared` / `insights` 的 `__all__` 是明確的 list literal，不是 globals() 推導
- stdlib 名稱沒有從 `insights_service` 匯出
- `insights_router` 與 scheduler 需要的名字都還在（漏匯出會 ImportError）
