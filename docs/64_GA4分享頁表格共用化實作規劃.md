- 連帶完成：docs/59 §P2-2「`GrowthBadge` 收進共用檔」（建議處理順序 6）

## 1. 問題

`SharedGA4Insight.jsx` 裡的 `ChannelsTable` / `LandingPagesTable` / `ItemsTable` /
`ItemLandingCrossTable` 與 `components/GA4Insights/*Tab.jsx` 的表格是兩套獨立程式
碼。欄位、格式化、成長標示、警示橫幅全靠人工同步。

docs/59 說「第三次漏掉只是時間問題」——實際盤點下來，**第三次已經發生了，只是
沒人回報**。這次動工前先逐欄比對，兩邊已經存在的落差：

| 快照類型 | 應用內分頁有、分享頁沒有 |
|---|---|
| 渠道對照 | `truncated` 橫幅（只顯示前 20 名的但書）、標籤欄的「佔收單」比例 |
| 到達頁 | 「轉換次數」「轉換率」表頭的 ⓘ 定義提示 |
| 商品 | **「瀏覽成長」整欄**（含「新進榜」標籤）、分類欄的 `✎` 自訂規則標記與來源提示 |
| 商品 | `used_fallback_conversion_metrics`、`category_breakdown_error` 兩條橫幅 |
| 商品頁面比對 | `used_fallback_conversion_metrics`、`mapping_query_error` / `landing_query_error` 兩條橫幅 |

橫幅缺漏比欄位缺漏更嚴重：收件人看到的是「商品全部未分類」「購買率 3.2%」，
卻沒有「這是抓取失敗造成的」「這是本地估算不是 GA4 官方數字」的但書，等於拿到
一份沒有註腳的報表。

另外 `GrowthBadge` 有四份完全相同的實作（docs/59 P2-2），全部都只在這些表格
內部使用。

## 2. 做法

新增 `frontend/src/components/GA4Insights/GA4InsightsTables.jsx`，放**純呈現層**
元件，由應用內分頁與分享頁共同 import：

```
GrowthBadge                    // 四份合一
PayloadWarnings                // 警示橫幅集中定義
ChannelsTable
LandingPagesTable
ItemsTable
ItemLandingCrossTable
```

介面約定（照 docs/59 建議：「吃 rows + payload，不含篩選/分頁邏輯」）：

```jsx
<XxxTable language={language} t={t} payload={payload} rows={rows} />
```

- `rows`：**呼叫端已經篩選 / 排序 / 分頁完**的列。表格自己不做這些事。
- `payload`：整份快照 payload，用來取表頭定義文字、`total_closing_conversions`、
  `compare_enabled` 等列以外的資訊。
- `ItemsTable` 另外吃選配的 `renderHeader(key, label, tooltip)`：應用內分頁傳入
  可排序表頭（帶箭頭與 onClick），分享頁不傳，落回內建的靜態 `<th>`。這是兩邊
  唯一真正的差異，用一個 render prop 收掉，不需要為它切兩份表格。

篩選 UI（分類按鈕、分類下拉、成長指標下拉）、`TablePager`、載入中/空狀態一律
留在呼叫端——分享頁只有分類篩選，應用內分頁有一整排條件，這部分本來就不該共用。

### 為什麼放新檔而不是 `GA4InsightsShared.jsx`

docs/59 P2-2 建議把 `GrowthBadge` 放進 `GA4InsightsShared.jsx`。該檔已經 829 行，
再塞約 400 行表格會變成什麼都有的雜物櫃。表格主體另立一檔、`GrowthBadge` 跟著
它唯一的使用處走，職責比較清楚；`GA4InsightsShared.jsx` 維持樣式/常數/`AIInsightNote`
等跨分頁小工具的定位不變。

## 3. 落差怎麼收

共用化本身會強制兩邊一致，收斂方向一律取**應用內分頁那份（較完整的）**，
也就是分享頁會補上第 1 節列出的全部欄位與橫幅。反方向（把分頁砍成分享頁那樣）
等於刪掉現有功能，不考慮。

`PayloadWarnings` 用一張表定義所有橫幅：

```js
{ id, kinds: ['item', ...], when: (payload) => boolean, text: (payload, t) => string }
```

`kinds` 決定哪種快照會檢查它。日後新增橫幅只要往這張表加一列，兩個表面同時生效
——這就是「靠結構保證，不是靠人記得」的具體形式。

## 4. 測試

新增 `frontend/src/components/GA4Insights/__tests__/GA4InsightsTables.test.jsx`，
針對共用元件本身：

1. 四張表格的欄位與資料格式化
2. `GrowthBadge`：次數類走成長率（`▲12%`）、比率類走百分點（`▲1.0pp`）且帶
   pp 說明的 `title`——docs/54 那個「5%→6% 不是成長 20%」的判斷
3. `is_new` 的列不顯示成長標示、只顯示「新」標籤
4. `PayloadWarnings`：每種 kind 只顯示屬於它的橫幅
5. 分享頁確實吃到共用元件（渲染 `SharedGA4Insight`，斷言那些**過去缺漏**的欄位
   與橫幅現在有出現）——這條是本次的回歸鎖，直接對應第 1 節的落差表

## 5. 不做的事

- 不動篩選/排序/分頁的狀態管理（那是 docs/59 P2-1，範圍大得多，另案）
- 不動 `*_GROWTH_METRIC_OPTIONS`：每個分頁欄位不同，docs/59 也明講維持各自定義
- 不動 `AlertsTab` / `OverviewTab` / `KpiTab`：分享頁沒有這三種快照，沒有第二套
  實作的問題
