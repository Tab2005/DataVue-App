# 40_GA4 商品頁面與商品轉換率交叉對照擴充構想

## 背景

在確認「商品頁面的轉換率該看哪個功能」時發現：目前系統對「商品頁面轉換率」這件事，其實拆成兩個**互相獨立、不互相參照**的既有功能，分別回答不同的問題，沒有一個地方能同時交叉對照「這個商品頁面」跟「這個商品」的表現。

## 現況（兩個既有、各自完整的功能）

### ① 到達頁（Landing Pages）分頁 — 以「頁面」為單位
- 欄位：`轉換率`（`session_key_event_rate`）
- 程式碼：`backend/modules/ga4/insights/landing_pages.py:60`，取 GA4 官方 `sessionKeyEventRate`，以 `landingPage` 維度分組
- 定義：從這個 URL 進站的所有工作階段裡，有百分之多少最後觸發了關鍵事件（例如購買）——**不管購買的是不是同一件商品**
- 「商品」分類靠 URL 路徑判斷（`/product`、`/shop`、`/p/` 等內建關鍵字，或 `GA4LandingPageRule` 自訂規則），跟商品本身（itemName/itemCategory）完全無關聯
- 回答的問題：「這個商品頁面帶來的訪客，這次來訪最後轉換的機率是多少」

### ② 商品（Items）分頁 — 以「商品本身」為單位
- 欄位：`瀏覽後購買率`（`purchase_to_view_rate`）
- 程式碼：`backend/modules/ga4/insights/items.py:90`，取 GA4 官方 `purchaseToViewRate`（使用者去重），以 `itemName` 維度分組
- 定義：看過這個商品（`view_item` 事件）的使用者裡，有百分之多少後來買了它——**不管是從哪個頁面看到的**
- 回答的問題：「這個商品本身，被看到之後有多少人會買」

## 缺口

系統目前**沒有**「單一商品頁面 × 單一商品」的交叉視圖，例如：
- 某個商品的「專屬詳情頁」，同時呈現「這個頁面的工作階段轉換率」和「這個商品的瀏覽後購買率」，讓兩個數字放在一起比較
- 找出「頁面轉換率低，但商品本身瀏覽後購買率不低」這種情況（可能代表頁面設計/載入速度問題，而非商品吸引力問題），或反過來的情況

目前這兩張表使用不同的 GA4 維度（`landingPage` vs `itemName`），GA4 Data API 本身要同時查詢這兩個維度也有已知的相容性限制（`items.py` 裡 `ITEM_METRICS_FALLBACK` 那段容錯邏輯就是在處理 `itemName` 與部分官方比率指標無法同查的問題），交叉關聯並非簡單加一個維度就能做到，需要另外設計資料串接方式（例如：先取得該商品的主要到達頁 URL，再分別查兩邊數據後在應用層合併；或改用 `itemName` + `landingPage` 雙維度查詢並驗證 GA4 是否支援、精準度是否足夠）。

## 狀態

僅記錄構想，尚未排入實作規劃。之後若要做，需要先決定：
1. 合併視圖要放在到達頁分頁、商品分頁，還是獨立新分頁
2. 資料串接方式（雙維度查詢 vs 應用層合併兩支既有查詢）
3. 一個商品如果對應多個到達頁（同商品有多個入口頁）時的呈現方式
