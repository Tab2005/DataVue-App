# 41_GA4 到達頁依流量管道拆分轉換率擴充構想

## 背景

在確認到達頁的轉換率怎麼算時發現：目前「到達頁」分頁顯示的轉換率是**跨全部流量管道合計**算出來的，無法看出「這個到達頁，從自然搜尋來的訪客轉換率」跟「同一個到達頁，從付費廣告來的訪客轉換率」分別是多少。

## 現況

- 到達頁查詢（`backend/modules/ga4/insights/landing_pages.py:20-24`）只用單一維度 `landingPage`，`sessions`/`sessionKeyEventRate` 等指標都是該頁面**全部渠道加總**後的結果
- 渠道對照分頁（`backend/modules/ga4/insights/channels.py`）則是反過來，只用渠道相關維度（`default_channel_group`/`source_medium`/`source`/`medium`/`campaign`，見 `insights_router.py` 的 `ChannelDimension` 白名單），完全不帶 `landingPage`
- 兩個功能都各自完整、獨立運作，但沒有「頁面 × 渠道」交叉拆分的版本

## 缺口

想知道「某個到達頁，依渠道拆開後轉換率分別是多少」時，目前系統做不到；只能看到頁面總轉換率，或渠道總轉換率，兩者無法交叉。

## 最終定案設計（討論後拍板，方案 A：篩選式下拉，不做展開式下鑽）

放棄「頁面 × 渠道」全展開的下鑽 UI（列數會膨脹到頁面數×渠道數，例如 477 個到達頁就快 3000 列，代價太高），改用**篩選式**設計：使用者選定「只看某個渠道」後，到達頁表格**列數不變**（還是一頁一個到達頁），但工作階段/轉換次數/轉換率/跳出率這幾欄，重新查詢成「只算這個渠道」的數字。不選則維持現況（跨全部渠道合計）。

**兩層下拉選單，完全複用渠道對照分頁既有的東西，不新建選項：**

1. **維度選單**：直接複用 `CHANNEL_DIMENSION_OPTIONS`（`frontend/src/components/GA4Insights/GA4InsightsShared.jsx:279`）跟後端 `ChannelDimension` 白名單（`insights_router.py`）——同樣 5 個選項（工作階段主要管道群組/來源媒介/來源/媒介/廣告活動）
2. **渠道值選單**：選了維度後，動態帶出該維度底下實際存在的渠道值（例如選「來源/媒介」後，選項會是 `google / organic`、`google / cpc`、`direct / (none)` 這種實際值），供使用者選一個當篩選條件
   - 渠道值清單直接沿用 `/channels` 端點既有回傳的 `payload.channels[].channel` 就有了，不用另外做一支「列出某維度所有渠道值」的新端點

**後端查詢方式：** 只取 `CHANNEL_DIMENSION_MAP[dimension][0]`（工作階段那一半，不用 firstUser 那一半，理由見上一節討論）對應的 GA4 維度名，查詢時 `dimensions=["landingPage", 該維度]`，並在 GA4 Data API 加 `dimensionFilter` 把該維度鎖定在選定的渠道值——這樣 GA4 端就先過濾好了，回傳結果本來就是「每個到達頁一列」，不會有列數膨脹的問題，也不用在應用層再手動彙總。

**快照 kind 命名需要跟著擴充：** 目前 `key_event` 篩選已經會讓 `kind` 變成 `landing_page:{key_event}`（維持 AI 解讀/快照各自獨立、不互相覆寫）。渠道篩選要比照同一套規則，繼續在 `kind` 後面疊加渠道篩選資訊（例如 `landing_page:{key_event}:{channel_dimension}:{channel_value}`），確保「篩了不同渠道」也是各自獨立的快照，不會互相覆寫彼此的 AI 解讀或分享連結——這樣也代表 39 號分享連結功能會自動對這個新篩選結果生效，不用額外開發。

**GA4 API 相容性仍需要實測驗證**：`sessionKeyEventRate` 搭配 `dimensionFilter` 是否會有計算口徑上的落差（例如濾掉其他渠道後，這個指標的分母定義會不會跟著變），需要對照 GA4 官方文件跟實測資料確認，不能只憑程式碼推斷。

構想已定案（方案 A + 複用現成下拉），下一步是寫成實作規劃文件（見 [[42_GA4_到達頁渠道篩選實作規劃]]）。與 [[40_GA4_商品頁面與商品轉換率交叉對照擴充構想]] 屬於同類性質的缺口，但 40 號那個交叉對照因為牽涉不同維度尺度（itemName vs landingPage）且已知有 GA4 相容性限制前例，複雜度更高，暫不合併處理。
