# 42_GA4 到達頁渠道篩選實作規劃

## 背景

延續 [[41_GA4_到達頁依流量管道拆分轉換率擴充構想]] 定案的方案 A：在到達頁分頁加兩層下拉選單（維度＋渠道值），選定後把該頁面的工作階段/轉換次數/轉換率/跳出率重新查詢成「只算這個渠道」的數字，列數不變、複用渠道對照既有的維度選項。本文件把定案的設計拆成可依序執行的實作步驟。

## 現況程式碼位置

- 到達頁查詢：`backend/modules/ga4/insights/landing_pages.py`（`get_landing_pages`，目前只帶 `landingPage` 單一維度）
- 渠道維度白名單／對照表：`backend/modules/ga4/insights/_shared.py`（`CHANNEL_DIMENSION_MAP`），`backend/modules/ga4/insights_router.py`（`ChannelDimension` Literal）
- 前端維度選項：`frontend/src/components/GA4Insights/GA4InsightsShared.jsx:279`（`CHANNEL_DIMENSION_OPTIONS`）
- GA4 查詢底層：`backend/modules/ga4/service.py`（`GA4AnalyticsService.get_analytics`，實際組 `RunReportRequest` 的地方）
- 快照模型：`backend/database/models/ga4_insights.py`（`GA4InsightsSnapshot`，唯一鍵 `property_id + kind + date`）

## 關鍵發現（規劃時確認、會影響工作量估計）

**GA4Service 目前完全不支援 dimension filter。** 查過 `modules/ga4/service.py`，三個組 `RunReportRequest` 的分支（不分維度／分頁／全量拉取）都只有 `dimensions`/`metrics`/`date_ranges`/`limit`/`offset`，沒有任何 filter 參數。這代表「渠道值篩選」不是加一個參數就好，是要新增 GA4 Data API 的 `FilterExpression`/`Filter.StringFilter` 支援。好消息是 GSC 模組（`backend/gsc_service.py` 的 `dimension_filters` 參數）已經有「server-side dimension filter」這個模式的前例可以參考設計形狀，但 GA4 跟 GSC 兩邊 API 的 filter 物件結構不同，不能直接複製程式碼，只能參考設計思路。

## 實作步驟（依序執行）

### 步驟 1：GA4Service 加上 dimension filter 支援 ✅ 已完成
- 檔案：`backend/modules/ga4/service.py`
- `get_analytics` 新增可選參數 `dimension_filter: Tuple[str, str] | None`，代表 `(維度名, 篩選值)`
- 三個 `RunReportRequest` 組建分支都接上：用 `google.analytics.data_v1beta.types.FilterExpression` + `Filter` + `Filter.StringFilter`（`match_type=EXACT`）組出 `dimension_filter=` 參數；沒有篩選時完全不帶這個欄位（已用 protobuf 的 `in` 判斷驗證向下相容）
- 快取鍵（`generate_cache_key`）已把 filter 條件編進去
- `ga4_service.py`（轉發層）已補上透傳參數
- 測試：`backend/tests/test_ga4_module_refactor.py` 新增 2 個單元測試

### 步驟 2：到達頁查詢邏輯加渠道篩選 ✅ 已完成
- 檔案：`backend/modules/ga4/insights/landing_pages.py`
- `get_landing_pages` 新增參數 `channel_dimension: str | None`、`channel_value: str | None`（兩者必須同時有值或同時沒有，其中一個缺另一個回 `ValueError`；`channel_dimension` 也會驗證是否在 `CHANNEL_DIMENSION_MAP` 白名單內）
- **實作時修正了原規劃的一個誤解**：GA4 Data API 的 `dimensionFilter` 是獨立於 `dimensions`（group by）之外的篩選條件，不需要把被篩選的維度也放進 `dimensions` 才能生效。所以主查詢跟關鍵事件分項查詢的 `dimensions` 完全不用改動（維持 `["landingPage"]` / `["landingPage", "eventName"]`），只加上 `dimension_filter=(CHANNEL_DIMENSION_MAP[channel_dimension][0], channel_value)` 即可，回傳列的形狀（一頁一列）不受影響——比原規劃更簡單
- 關鍵事件分項查詢也一併帶上同樣的渠道篩選，主表格數字跟分項明細數字才會對得起來
- **`kind` 命名也修正了原規劃**：原本設想直接把 `channel_value` 串進 `kind`（例如 `landing_page:{channel_dimension}:{channel_value}`），但 `channel_value` 是自由文字（可能是完整 UTM campaign 名稱），直接串入有撐爆 `String(80)` 欄位、或不同篩選值被截斷後誤判成同一筆快照的風險。改成對 `(channel_dimension, channel_value)` 取短雜湊當後綴，例如 `landing_page:ch_3f9a1b2c4d`（有 `key_event` 時是 `landing_page:{key_event}:ch_xxx`）。`payload` 裡仍原樣存 `channel_dimension`/`channel_value` 明文供前端顯示，只有快照的 lookup key（`kind`）改用雜湊。這樣不同渠道篩選各自存成獨立快照，AI 解讀/[[39_GA4_轉換洞察快照分享連結實作計劃|分享連結]]不會互相覆寫——39 號分享連結功能會自動對篩選後的結果生效，不用額外開發
- 測試：`backend/tests/test_ga4_landing_page_rules.py` 新增 4 個測試（filter 正確傳遞且只取工作階段那一半、成對驗證、白名單驗證、不同篩選值各自獨立存快照）

### 步驟 3：API 端點加參數 ✅ 已完成
- 檔案：`backend/modules/ga4/insights_router.py`
- `GET /landing-pages` 新增 `channel_dimension: ChannelDimension | None = Query(None)`、`channel_value: str | None = Query(None, max_length=100)`
- 驗證分兩層：`channel_dimension` 不在白名單內時，FastAPI/pydantic 的 `Literal` 型別直接回 422（跟 `dimension` 白名單同一套機制）；兩者沒有成對提供則由 service 層的 `ValueError` 經既有的 `except (RuntimeError, ValueError)` 轉成 400
- 測試：`backend/tests/test_ga4_landing_page_rules.py` 新增 3 個端點測試（成對提供正常回應、未知維度 422、只給一個回 400）

### 步驟 4：前端 API client ✅ 已完成
- 檔案：`frontend/src/services/ga4InsightsService.js`
- `getLandingPages` 簽名加上 `channelDimension`、`channelValue`，兩者都有值時才帶進 query string（只給一個時視同不篩選，避免組出後端會拒絕的不成對請求）

### 步驟 5：前端「渠道值」清單來源 ✅ 已完成
- 不新增後端端點：渠道值清單直接復用既有 `getChannels(propertyId, days, dimension)` 回應裡的 `payload.channels[].channel`
- `GA4Insights.jsx` 新增 `loadLandingChannelValues(pid, days, dimension)`，選了「維度」後呼叫一次 `getChannels` 取得該維度底下實際存在的渠道值，存進 `landingChannelValues` 供第二層下拉選單使用（這次呼叫是額外新增的，跟渠道對照分頁原本各自的抓取互不影響）
- 到達頁的天數（`landingDays`）切換時，若目前已選了維度，也會一併重新抓取渠道值清單，避免清單跟畫面實際查詢的期間對不上

### 步驟 6：前端 UI（到達頁分頁）✅ 已完成

- 在既有「全部關鍵事件」下拉下方，加兩個下拉：
  1. 維度選單：直接複用 `CHANNEL_DIMENSION_OPTIONS`，預設「不篩選渠道」
  2. 渠道值選單：選了維度後才顯示，選項來自步驟 5 抓到的清單，抓取中會停用並顯示載入提示；預設「全部渠道」（等同不篩選，維持現況）
- 兩個下拉變動時都會觸發 `loadLandingPages` 重新查詢，用法比照現有 `landingKeyEvent` 的狀態管理模式；切換「維度」時會連帶清空已選的渠道值並重新查詢成不篩選狀態
- `AIInsightNote`／[[39_GA4_轉換洞察快照分享連結實作計劃|分享連結]]功能不用改：兩者都是讀取當下載入的 `landingSnapshot`（含篩選後的 `snapshot_id`），已經自動對篩選結果生效
