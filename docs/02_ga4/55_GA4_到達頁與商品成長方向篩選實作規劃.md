# 55_GA4 到達頁與商品成長方向篩選實作規劃

## 背景

延續 [[54_GA4_到達頁與商品上一期比較功能實作規劃]]：使用者測試「比較上一期」功能後，想進一步依「某個指標是上升還是下降」篩選表格列。

## 拍板決策

1. 兩個下拉選單：一個選「指標」，一個選「方向」（上升/下降，含「全部」不篩選）
2. 只針對**單一指標**篩選（不是「任一指標上升就顯示」），因為同一列不同指標的漲跌可能不一致，篩多個指標會有 AND/OR 語意不清楚的問題
3. **不**同步到 AI 解讀（`buildPayload`/`contextLabel` 維持現況，不受這個篩選影響）
4. **不**同步到分享連結網址（不加新的 URL 參數，分享頁也不用跟著加這組下拉）——理由：分享連結目前只有 `?category=` 一個參數，如果每個篩選條件都疊加，網址跟分享頁維護成本會一直墊高，且「上升/下降」偏向細節操作，分享給別人看全部資料自己判斷更實用

## 技術方向

- 兩個下拉選單只在「比較上一期」開關**打開時**顯示（沒開比較就沒有成長資料可篩，維持現況隱藏）
- 指標選項依分頁各自的比較欄位：
  - 到達頁：工作階段（`sessions_growth_rate`）/ 轉換次數（`conversions_growth_rate`）/ 轉換率（`session_key_event_rate_delta_pp`）/ 跳出率（`bounce_rate_delta_pp`）
  - 商品：瀏覽數（`views_compare_growth_rate`）/ 加購率（`cart_to_view_rate_delta_pp`）/ 購買率（`purchase_to_view_rate_delta_pp`）/ 營收（`revenue_growth_rate`）
- 方向選項：全部（不篩選，預設）/ 上升（值 > 0）/ 持平（值 = 0）/ 下降（值 < 0）
- 篩選是純前端二次篩選，疊加在既有的分類篩選（到達頁按鈕/商品下拉）跟商品搜尋框之後，不用改後端、不用多打 API
- **新頁面/新商品（`is_new`）沒有比較數值**：選了「全部」以外的方向時，這些列會被篩掉（因為無法判斷漲跌）；選「全部」時維持顯示（現況不變）
- 「比較上一期」開關關閉時，兩個下拉一併隱藏；重新開啟比較時方向/指標下拉重置回預設（全部/未選）值，避免殘留舊篩選條件卻沒顯示 UI 造成困惑
