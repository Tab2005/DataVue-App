# 41_GA4 到達頁依流量管道拆分轉換率擴充構想

## 背景

在確認到達頁的轉換率怎麼算時發現：目前「到達頁」分頁顯示的轉換率是**跨全部流量管道合計**算出來的，無法看出「這個到達頁，從自然搜尋來的訪客轉換率」跟「同一個到達頁，從付費廣告來的訪客轉換率」分別是多少。

## 現況

- 到達頁查詢（`backend/modules/ga4/insights/landing_pages.py:20-24`）只用單一維度 `landingPage`，`sessions`/`sessionKeyEventRate` 等指標都是該頁面**全部渠道加總**後的結果
- 渠道對照分頁（`backend/modules/ga4/insights/channels.py`）則是反過來，只用渠道相關維度（`default_channel_group`/`source_medium`/`source`/`medium`/`campaign`，見 `insights_router.py` 的 `ChannelDimension` 白名單），完全不帶 `landingPage`
- 兩個功能都各自完整、獨立運作，但沒有「頁面 × 渠道」交叉拆分的版本

## 缺口

想知道「某個到達頁，依渠道拆開後轉換率分別是多少」時，目前系統做不到；只能看到頁面總轉換率，或渠道總轉換率，兩者無法交叉。

## 如果要做，預期的工作範圍

1. **後端查詢改雙維度**：GA4 Data API 查詢同時帶 `landingPage` + 一個渠道維度（例如 `sessionDefaultChannelGroup`），把 `sessions`/`sessionKeyEventRate` 依「頁面＋渠道」組合分別取出，而不是現在的頁面總計
2. **資料量與呈現方式需要重新設計**：頁面數 × 渠道數組合下，列數會大幅膨脹（例：50 個到達頁 × 6 種渠道 = 300 列），不適合再用現在攤平的表格呈現，較合理的做法是「點某個到達頁展開看渠道拆解」的下鑽（drill-down）UI
3. **GA4 API 相容性需要實測驗證**：`sessionKeyEventRate` 這類指標在雙維度查詢下是否會像商品分頁（`itemName` 搭配官方比率指標）一樣踩到 GA4 的維度/指標相容性限制，程式碼裡目前沒有這個組合的前例可參考，需要實際測試才能確認
4. 渠道維度要沿用渠道對照分頁既有的白名單（`default_channel_group`/`source_medium`/`source`/`medium`/`campaign`）中的哪一個/是否要讓使用者可切換，也需要決定

## 狀態

僅記錄構想，尚未排入實作規劃。與 [[40_GA4_商品頁面與商品轉換率交叉對照擴充構想]] 屬於同類性質的缺口（既有單一維度功能之間缺乏交叉視圖），未來若要排入開發，兩者的技術難點（維度組合的呈現方式、GA4 API 相容性驗證）可以一併評估。
